# MASTERY — API Contracts & Integration Conventions

**Version:** 1.0  
**Base URL:** `/api/v1`  
**Data Format:** JSON (`application/json`)  
**Phase:** 01/11 — Foundation Contracts  

---

## 1. Global API Design Conventions

### 1.1 Versioning
All domain routes reside strictly under `/api/v1`. Route naming uses lowercase, hyphen-separated kebab-case:
- Correct: `/api/v1/academic-data/imports`
- Incorrect: `/api/v1/academicData/getImports`

### 1.2 HTTP Verbs & Idempotence
- `GET`: Safe, read-only retrieval. Never mutates server state.
- `POST`: Creation of a new resource or execution of an action (e.g. running an assessment evaluation).
- `PUT`: Complete idempotent replacement of an existing resource.
- `PATCH`: Partial modification of resource fields.
- `DELETE`: Deletion or soft-deletion of a resource.

### 1.3 Standard Response Headers
- `Content-Type`: `application/json`
- `X-Process-Time-Ms`: Server execution latency in milliseconds.
- `Cache-Control`: `no-store, max-age=0` for dynamic academic analytics.

## 2. Centralized Error Response Contract

All errors generated by FastAPI (HTTPExceptions, ValidationErrors, or unhandled 500 exceptions) return a standardized JSON contract:

```json
{
  "status": "error",
  "error_type": "ValidationError | HTTPException | InternalServerError",
  "detail": "Descriptive message or array of field validation violations",
  "status_code": 422,
  "path": "/api/v1/endpoint"
}
```

### HTTP Status Code Semantics
- `200 OK`: Request succeeded.
- `201 Created`: Resource successfully created.
- `400 Bad Request`: Business rule validation violation.
- `401 Unauthorized`: Missing or expired Bearer token.
- `403 Forbidden`: Authenticated user lacks the required RBAC role.
- `404 Not Found`: Resource does not exist.
- `422 Unprocessable Entity`: Request body or parameter schema mismatch.
- `503 Service Unavailable`: External resource unreachable (e.g. database offline).

## 3. Foundation Endpoint Specifications

### 3.1 Service Identification
- **Endpoint:** `GET /`
- **Description:** Returns service root identification and diagnostic endpoints.
- **Response Schema:**
```json
{
  "app": "MASTERY",
  "tagline": "Beyond Marks. Towards Mastery.",
  "description": "AI-powered Student Performance Analytics...",
  "version": "0.1.0",
  "api_v1_docs": "/docs",
  "api_v1_health": "/api/v1/health",
  "api_v1_db_health": "/api/v1/health/database"
}
```

### 3.2 Application Health Check
- **Endpoint:** `GET /api/v1/health`
- **Description:** Returns high-level application health and subsystem statuses without failing if optional services are not configured.
- **Response Schema:**
```json
{
  "status": "healthy",
  "app_name": "MASTERY",
  "environment": "development",
  "version": "0.1.0",
  "timestamp": "2026-11-15T11:00:00Z",
  "services": {
    "api": "operational",
    "database": "connected | unconfigured | disconnected",
    "ai_engine": "configured | unconfigured",
    "supabase_auth": "configured | unconfigured"
  }
}
```

### 3.3 Database Health Check
- **Endpoint:** `GET /api/v1/health/database`
- **Description:** Explicitly probes database connectivity with graceful fallback when unconfigured.
- **Status Codes:**
  - `200 OK`: When DATABASE_URL is not configured (`status: "unconfigured"`).
  - `200 OK`: When database is reachable (`status: "connected"`).
  - `503 Service Unavailable`: When DATABASE_URL is set but connection times out or fails (`status: "disconnected"`).
- **Response Schema:**
```json
{
  "status": "connected | unconfigured | disconnected",
  "configured": true,
  "message": "Database connection operational.",
  "latency_ms": 3.42,
  "timestamp": "2026-11-15T11:00:00Z"
}
```

## 4. Future Domain Endpoint Specifications (Phases 02–08)

### Module 01: Academic Data Hub
- `POST /api/v1/academic/students/import`: Bulk student roster upload (CSV/Excel).
- `GET /api/v1/academic/students/{id}/timeline`: Retrieve student academic evidence ledger.
- `POST /api/v1/academic/attendance/bulk`: Ingest attendance session records.

### Module 02: Syllabus & Competency Intelligence
- `POST /api/v1/syllabus/upload`: Ingest course syllabus PDF for extraction.
- `GET /api/v1/syllabus/{course_id}/tree`: Get verified topic & outcome hierarchy.
- `POST /api/v1/syllabus/{id}/approve`: Faculty approval of extracted topics.

### Module 03: Continuous Assessment Engine
- `POST /api/v1/assessments/generate-questions`: AI-assisted question generation.
- `GET /api/v1/assessments/{id}/session`: Student test launch payload.
- `POST /api/v1/assessments/attempts/{id}/submit`: Multi-modal submission & scoring.

### Module 04: Mastery Analytics
- `GET /api/v1/mastery/students/{id}/topics`: Topic-level calibrated mastery scores.
- `GET /api/v1/mastery/cohort/{course_id}/heatmap`: Aggregated cohort mastery heatmap.
- `GET /api/v1/mastery/discrepancies`: Faculty review of grade vs mastery mismatches.

### Module 05: Academic Risk Prediction
- `POST /api/v1/risk/screen`: Trigger cohort risk classification pipeline.
- `GET /api/v1/risk/alerts`: Faculty review queue of explainable risk alerts.
- `GET /api/v1/risk/students/{id}/attributions`: Feature attribution breakdown.

### Module 06: Personalized Interventions
- `POST /api/v1/interventions/plans`: Create customized student support plan.
- `GET /api/v1/interventions/students/{id}`: Student active growth tasks.
- `POST /api/v1/interventions/tasks/{id}/verify`: Faculty verification of completed work.

### Module 07: Career Readiness Intelligence
- `GET /api/v1/career/roles`: Standardized industry competency benchmarks.
- `POST /api/v1/career/evidence/verify-github`: External engineering verification.
- `GET /api/v1/career/students/{id}/radar`: Placement readiness radar & skill gaps.
